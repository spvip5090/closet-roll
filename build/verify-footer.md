
## stats.js（実測推定）の扱い

採点変更で旧 stats.js の推定値は無効になるため、**v2 エンジンで各モード100,000回を回して再生成し、work/stats.js を差し替えた**（形式は従来と同一、合計100,000/モードで検証済み）。表示と実エンジンの不整合は解消済み。なお FASHION DISASTER（10点以下）は v2 では「着用可能性の重大問題が複数重なる」場合にのみ到達し、ランダム100,000回では 0 件だった（v1 の 0.77% は −24 級ルールの重ね掛けによるもの）。specials の判定条件自体は変更していない。

## SPEC に対して未対応・割り切った点

- **高額で壊滅的の得点が52点**（SPEC目安は20–50）。重大な不調和が1件だけの場合は「52点上限」の設計を優先したため。分類はダサい／不成立、称号・コメントは厳しい内容になり、理由も明示される。2件以上の重大不調和では45点上限が効く。
- **10点以下はランダム抽選ではほぼ発生しない**（100,000回で0件）。到達可能性はある（肌着トップス＋肌着ボトムス＋室内履き等の複合で1桁台になることを計算上確認）が、意図的に頻度を上げるための乱数・恣意的減点は入れていない。
- **季節感は独立軸にしていない**。属性の確証が取れる商品が5.1%しかないため、季節の不一致はシルエット軸のペアルール（防寒×サンダル等、名前証拠ベース）として扱った。
- **色の写真判定には誤差がある**（モデル着用・背景）。名前由来を優先し、写真由来は調和判定の重みを下げてある。全件の目視確認はしていない。
- **同一商品の色違いがカタログに存在しない**ため、「色だけ変更」テストは同一商品ライン（GU グラフィックT ジョジョ 5→7）で代替した。
- テストコーデ15パターンは全て構成できたが、各パターン1例ずつの提示（SPECの「複数例」までは拡張していない）。探索はシード固定のランダムサーチ（各30,000試行）で再現可能。
- アフィリエイト導線・図鑑UI改善は本タスクの範囲外（未着手）。integrations.js は無改変。
- 実機ブラウザでの表示確認はこの環境では行えていない。Node での構文チェック、エンジン単体実行、extras.js 連携（titleFor/specials/rarityText/coverLine）の煙テストは合格。最終的な目視確認は work/ をブラウザで開いて1回引くのが最速。

## 再現方法

- 属性再生成：`python3 build/gen_attrs.py`
- テストコーデ：`node build/tests.js`（結果は build/tests-frag.md / tests-out.json）
- シミュレーション＋stats再生成：`node build/sim.js`
- 連携煙テスト：`node build/smoke.js`
