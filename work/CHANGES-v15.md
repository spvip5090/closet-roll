## 1. 画面分離（旧セクション → 新ビュー対応表）

CSSで他を隠す」だった。v15では `<main>` 直下に5つの
`<section class="view">` を置き、常時ちょうど1つだけを表示する
（display切替。スクロール誘導は廃止）。

| `#stage`＋`#result`＋`.controls`＋`.note`＋`#moreResult`＋`#after-result` | `#viewGacha` ガチャ | 開封演出、結果スプレッド（項目4）、もう1パック／スキップ／シェア、ポスター・お気に入り・対決 |
| `details#bookBox`（`#archive`内） | `#viewCatalog` 図鑑 | `#bookCounts`／検索・絞り込み／`#book`／`#bookMore` を details から独立画面へ |

## 3. ナビゲーション／戻るの設計

ルーターは extras.js（`showView` / `applyView` / `pushNav` / `onPopState`）。
内部状態 `navState={view, sub}` が表示中ビューと履歴エントリの両方を映す。

- **ビュー切替**： 全切替で `window.scrollTo(0,0)`（先頭リセット）。
- **ブラウザの戻る（実ページ）**： 切替ごとに
  `history.pushState({cr:1, view, sub})`（URLは変えない）。popstate では
  エントリの state からビューを復元する。`finish()` が結果表示時に
  `history.replaceState` で対戦用ハッシュ（`#v6-…`）を書く際、state は
  `navHistState()` で再スタンプされるため、描画後もそのエントリの
  ビュー所属は失われない。state が無いエントリ（初期エントリ等）では
  ハッシュがコーデ形式ならガチャ、それ以外はホームと推定する。
- **クローゼットのサブ状態**： 採点結果表示は `{view:'closet', sub:'result'}`
  の別エントリ。戻るボタン／ブラウザ戻るのどちらでもビルダーに戻る。
  ボタンの実体は history.back()（popstate が DOM 復元を担当）＋450ms の
  フォールバック（履歴が使えない環境では直接ビルダー復元）。
- **戻るボタンの統一（監査結果）**： v13ではクローゼット画面に
  「← もどる」（ビューを出る）と「← コーデ組みに戻る」（結果→ビルダー）
  の2つが同居していた。v15では後者を唯一のパターンとして
  **「← もどる」** に改称・一本化し、前者は削除（ビューを出る操作は
  タブバーが担う）。詳細シートの ×（モーダルを閉じる）は別パターンの
  まま維持。
- **ウィジェット試用版での動作**： 試用ビルドは localStorage が
  メモリ内シム（`window.__crMem`）に置換される。ルーターは
  `inWidget()` でこれを検出し、pushState／replaceState を一切行わない
  （iframe の履歴を汚さない）。遷移はすべて in-app 操作（タブ、CTA、
  戻るボタン）で完結し、戻るボタンは直接ビルダー復元に落ちる。
  popstate リスナ自体は無害なので登録したまま。
- **共有／対決リンクの着地**： `restore()` は初回ロード／リンク貼り付け／
  履歴クリック（hashchange）でガチャビューへ遷移してから結果を描画する。
  一方、戻る／進む由来の hashchange は popstate がビューを govern する
  ため、`popNavRecent()`（600ms 窓）で restore を抑制する。
  深い戻る連鎖で URL のコーデと表示中コーデがずれた場合は、ガチャ
  タブの再タップで URL のコーデを再描画する（`syncGachaToHash`）。

## 4. 結果画面：誌面スプレッド化

`#result` の内部を「見出し→写真とスコアのスプレッド→ミレイの欄」の
3段に再構成（ID はすべて不変、DOM 順のみ変更）。

1. **見出し**： `#outcome` バナー（キッカー／大見出し／インプレッション）。
   クローゼット時はその上に `#closetMark`。
2. **スプレッド**（`.spreadTop`、2カラムグリッド）：
   - 左（1.18fr）： `#grid` の5枚の写真モザイク（2列＋5枚目は横長に
     スパン）。写真が視覚の主役。
   - 右（.82fr）： `#scores` を表紙のカバーラインとして再構成 —
     YOUR LOOK 見出し＋コーデ名、コーデ総額（セリフ体）、総合点
     （56px セリフ数字）／豪華さ／調和、ボーナスチップ、称号・
     レアリティ・対決状況。
3. **ミレイの欄**（`.mireiCol`、二重罫の下）： 一行コメント `#review` を
   欄のリード文として左寄せで置き、続く details（初期表示は開いた
   まま）に署名バッジ（写真なし・M のモノグラム＋名前＋肩書き）、
   パラメーター、総評全文 `#reviewFull` を「コラム」として収める。
   怒りのヒート表現（`details.rageN .personaInitial`）はバッジが
   details 内に残ったため CSS・resultExtras とも無変更。

**ファーストビュー**： 標準的なスマホ縦画面（例 390×844）では、
マストヘッド＋モード切替の下に、見出し→スプレッド（5枚すべてと
スコア・総額）→ミレイ欄のリードまでがスクロールなしで入る。
小さい画面向けに `max-height:740px` で見出し余白と写真高を詰める
調整を追加（それ以下の極小画面では総評リードまで僅かにスクロール）。

クローゼット相談結果も同じスプレッド規律で `#closetResultSlot` 内に
描画され、`fromCloset` の差別化（赤罫＋相談室マーク＋パーセンタイル
なし）は従来通り。

## 5. 機能・データの不変性

- localStorage キー（`closet-editorial-v1`）と保存形式は無変更。
  既存プレイヤーのデータは同一に読み込まれる。
- ガチャ経路の採点・ペルソナ出力はバイト同一（test-persona 7,301件が
  期待値無変更で合格）。特殊パックとその秘匿性も無変更。
- 対決リンク（`#v6-…` 等の全形式）、履歴・お気に入りからの復元、
  購入リンクのフォールバック、デイリー、図鑑の検索・NEW バッジ、
  記録グリッドはすべて従来通り動作する。
- **遅延描画**： 図鑑はビュー初回表示時のみ構築（`activateBook()` が
  ラッチ）。以降のタブ切替では DOM を再構築せず、件数行のテキスト
  だけを更新する。記録の履歴リストもマイページ初回表示まで描画しない
  （`viewSeen.mypage` ゲート、旧 `details#archive.open` ゲートの置換）。
  写真は従来通り `loading="lazy"`、非表示ビューの画像は読み込まれない。
